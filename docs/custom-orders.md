# Special requests and custom invoices

Customers can expand “Request another option / upload a design” beneath each configurator dropdown. The original catalog choice remains selected. Their replacement instructions and private file references are stored separately and travel with private saved builds, backups, design-review requests, and journals. Public build links, comparison polls, and published Circle stories exclude them. Original JPG, PNG, WebP, and PDF files are stored in the private R2 `BUCKET` binding, with 10 MB per file, three per option, and eight per guitar.

Customers submit the full configuration through the personal design-review form. A request freezes the configured price from the server catalog. The request appears in the owner-only Workshop desk; the customer may also open an email draft containing the specifications and a workshop link. These customer notifications are not automatically emailed.

In Workshop desk, open a design review and use the Custom invoice editor. It retains the original specification and subtotal, accepts positive additions or negative credits, and provides a free-text agreed specification and estimated timing. Save a draft or review and create a private invoice link. “Email invoice” opens a draft in the owner's email app; it does not automatically send messages. The owner can copy the same link into an existing email conversation. Issued versions are immutable. Void an unpaid invoice before replacing it; open Stripe checkout is expired first, and processing/completed payments cannot be voided.

The private invoice page shows the original selections, requested replacements, artwork downloads, agreed specification, itemized price differences, and subtotal. The customer accepts the specification and continues to the existing Stripe Checkout integration, which collects the address, terms acceptance, and final tax. This is a Fostinis invoice/order page; it does not create or send a Stripe Invoicing object or enable an additional Stripe Billing product. Printable invoice totals include verified tax after payment. This integration retains the existing automatic-tax configuration and US shipping policy.

The owner controls price adjustments on the server. Client totals cannot replace approved prices. A $4,000 configured price plus a $100 adjustment becomes a $4,100 guitar subtotal before applicable tax. Catalog checkout remains blocked for unapproved custom requests. Signed existing Checkout webhooks verify the actual Stripe session, mode, amount, order, invoice ID, and invoice revision before updating invoice status and linking a real paid order to the customer journal. Test payments remain distinct. Customer page refresh also reconciles payment status.

Migration `0005_rich_prism.sql` adds private upload metadata and custom invoices. Existing request, order, payment, and authentication data are preserved. The existing Stripe runtime secrets and webhook endpoint are reused. No real customer invoices, messages, or payments are generated during automated verification.
